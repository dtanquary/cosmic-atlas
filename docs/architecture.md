# Architecture

## Stack and boundaries

Vite + strict TypeScript + Three.js WebGL2. A small semantic HTML/CSS HUD owns controls; the renderer owns camera, batched point geometries, selection, and measurements. Galaxy records never become individual scene objects or DOM elements. Python/NumPy/Astropy prepare immutable static datasets; the browser never downloads FITS or computes cosmological integrals.

## Coordinate conventions

Mpc internally. Observer at zero. Equatorial coordinates: x = D cos(dec) cos(ra), y = D cos(dec) sin(ra), z = D sin(dec). North celestial pole is +z; the camera uses +z as its up vector. DESI distances use Astropy's Planck18 (including its radiation/neutrino parameters). A validated high-resolution lookup interpolates comoving distances for bulk conversion. Inspection and measurement retain float64 Cartesian values reconstructed from original RA/Dec and the stored derived distance. Render chunks use float32 positions relative to a float64 node center. The vertex shader subtracts camera position from node origin on the CPU before projection.

## Dataset contract v1

`manifest.json` identifies the dataset, source release/hash, filters, accepted/source counts, development subset status, cosmology, axes/units, bounds, and a flat octree. Node records contain id, bounds/center, represented count, stored point count, children, compressed point/metadata URLs, hashes and bytes. Bounds cover descendant points, not merely a sampled subset.

Point files use a 16-byte little-endian header: magic `0x43415431`, version 1, row count, reserved. Then contiguous XYZ float32 positions (3N) and uint32 stable dataset row IDs (N). Metadata files have the same header with magic `0x43414d31`; rows are 56 bytes: int64 TARGETID, float64 RA, DEC, Z, ZERR, comoving distance in Mpc, DELTACHI2. File transport is gzip, explicitly decoded in the worker. Metadata rows align with point rows. IDs are read with BigInt and shown as strings.

Node samples are deterministic hashes of real target IDs. Leaves contain all their assigned points. A render frontier contains either a parent sample or covered descendants; never both. Full detail requests all visible leaves. A parent remains visible while required descendants load. The UI distinguishes sampled coverage, full-detail loading, complete view, and failed/blocked detail. Counts mean dataset population, unique loaded render records, and points submitted for the current frame; submitted points may overlap or be clipped.

## Runtime

Flight settings visibility is UI state independent of pointer lock. Fly opens the editable speed panel; Start flying requests pointer lock. Escape ends capture but retains the panel and current speed. The slider is disabled while captured, when the wheel controls speed instead. Orbit, Milky Way, and Overview explicitly close the panel. The renderer's `onFlight` callback reports capture changes without deciding whether settings should be visible.

Auto fly is a separate, mutually exclusive movement state. The existing frame loop translates the camera and orbit target together along the camera's forward vector using the current speed and bounded frame delta. Orbit input is suspended during the straight pass, while the cursor remains free for the speed slider and stop button. Escape handles stopping before the form-control keyboard guard. Navigation/focus actions and tab hiding stop auto movement. No additional animation loop or per-galaxy work is introduced.

Camera travel (`travel.ts`) is the third movement state and also runs inside the existing frame loop. `focusAt(…, seconds)` keeps its instant path when `seconds` is 0; otherwise it stores a `travel` object holding the start and end poses, `move()` writes the interpolated orbit target, camera position and focus distance each frame before `controls.update()`, and the arrival frame performs the exact instant placement. The target is eased with smoothstep, the camera distance is interpolated in log space plus a hop of 1.3 × the target displacement (enough to see both endpoints at 50° fov in landscape), and the view direction follows the great circle. OrbitControls stay enabled throughout; their `start` event (pointer down or wheel), a newer focus, flight, auto fly or disposal cancels the travel, using the travel object itself as the token rather than the selection serial. `prefers-reduced-motion: reduce` selects the instant path. Every existing caller keeps `seconds = 0`; only opened saved views travel (1.5 s). Visits return the arrival promise: `visitCatalog` resolves true on arrival or false when the travel is cancelled (undefined when it bails before navigating), consistent with the other visits. The public `stopTravel()` halts an in-flight travel where it is, without repositioning, so a tour's Escape or Exit can interrupt a hop.

An abortable worker loader handles fetch, integrity checking, gzip decode, and typed arrays with transferable buffers. A bounded queue prioritizes coarse coverage and visible refinement. Frontier retention (`retain()`) cancels only streamed point requests: metadata and explicit priority loads, such as the points chunk a view link needs to derive a dense id and the queued profile-sidecar loads the model catalog requests with priority, finish even when the LOD frontier moves on (previously a moved frontier could cancel a queued profile request and raise a spurious "Some galaxy shapes could not load" notice). Resident chunks track their last use; eviction disposes GPU buffers and typed-array references. Selected metadata is independent of render residency. Memory accounting includes point arrays, corresponding GPU attributes, metadata, and in-flight reservations. Full detail stops loading with an explicit memory-limit state instead of silently changing mode.

On-demand GPU ID picking uses the same point geometry and camera as rendering, unblended integer-color IDs, and async readback. Dense IDs map back to node row metadata. The picker uses a small screen region and a larger hit radius for usability. Idle rendering stops; camera input, pending transitions, loads, and resize invalidate the frame. Tab visibility suspends animation.

Distance cues run in the existing point vertex shader with shared uniforms, without additional attributes, scene objects, or draw calls. Euclidean camera distance drives a smooth opacity fade and an optional capped 65% marker-size boost within 150 Mpc. Separate shared uniforms control fading and enlargement in both the visual and GPU ID passes; enlargement is off by default. The fade horizon expands continuously outside the catalog's bounding sphere and settles to a neighborhood range inside it. Opacity interpolates from 1 to a configurable floor. The display and ID pass discard only zero visibility, retaining even 0.5–1% floors. Annotation materials bypass the effect. Settings independently toggles fading and point enlargement, saving enlargement and the floor percentage in localStorage; positions and measurements remain unchanged. Submitted-point counts include distance-faded points.

## Catalog-wide galaxy models

`public/data/models/manifest.json` pins the DR1 source checksum, 14,140,375 observations, 1,010 profile assets, a small Gaussian library, and 3,128 exact named visual-type matches. The extractor uses the same accepted-row ordering as the existing position catalog, verifies node point/metadata hashes, and leaves those original assets untouched. Details and limitations are in [galaxy-detail.md](galaxy-detail.md).

Each gzip profile sidecar aligns one-for-one with its node's point rows. Its 16-byte little-endian header is magic `0x43415331`, version 1, count, reserved. Each 20-byte row holds float32 angular half-light radius, e1, e2, Sersic index, then uint32 flags. The low byte identifies the imaging fit (unknown/PSF/REX/EXP/DEV/SER); the next byte identifies a matched visual family (unknown/spiral/barred/elliptical/lenticular/irregular). These two classifications remain distinct. The complete sidecars are about 143 MB compressed; the model manifest is about 733 KB.

`ModelCatalog` uses a worker for checksum verification and decompression, with at most four nearby profile requests initiated by the candidate planner. Its LRU profile cache is bounded to 16 chunks and 48 MiB including reservations. Conservative per-node maximum radii avoid requesting shapes that cannot resolve on screen. At most every 250 ms during movement, or after relevant loads, the renderer scans packed positions only in nearby displayed chunks and ranks projected radii. Metadata is fetched only for the small selected/nearby set, supplying exact float64 centers and target IDs. Profile failures leave the point atlas available and expose Retry.

At most **12** DESI resolved models are resident, alongside six fixed nearby models and the Milky Way reference. The two original individually fitted previews stay pinned; the remaining slots favor the current selection and largest projected nearby galaxies. Resident exact centers/shapes remain candidates independently of the current point frontier; their scores receive a 30% margin over new candidates to reduce churn. Candidate identities are deduplicated. Separate nearby-layer selections do not consume DESI pool slots. Automatic replacements first fade to zero over 0.6 seconds, keeping their slot until the fade finishes; new automatic models start at zero and fade in. Explicit visits can immediately reserve a model for the intended destination. Removed models dispose their GPU geometry and materials. Generic structured models use one batched geometry of 12,000 light knots; NGC 3982 retains its 24,000-knot preview. There are no individual star objects or catalog-sized scene graphs. Combined CPU/GPU point, slot, metadata, profile cache, in-flight reservation and model attributes contribute to the existing managed memory accounting.

Each smooth volume analytically integrates at most 20 oblate Gaussian components along the front half of each camera ray. A conservative screen rectangle bounds each volume to one draw call when visible. Spiral/barred/irregular structure adds one batched draw. Double-precision CPU subtraction supplies camera-relative coordinates, allowing galaxy-scale precision and entry into the volume. Generic Sersic fits use the nearest library index in 0.1 steps; the original two profiles retain their individual fits.

Projected half-light radius drives the point/model crossfade from 0.6 to 5 CSS pixels (about 1.6 times farther than the previous 1–8 range). Candidate loading begins at 0.35 pixels, with a 0.25-pixel resident retention threshold. A float slot attribute per point (zero normally) indexes the small active-model origin/blend uniform arrays. Only matching rows are updated when model residency changes. This avoids testing every vertex against a list of models. The original dense ID and node-row picker are retained, and an analytic body hit test supports selecting the visible galaxy away from its center.

Distance cues shorten the point fade horizon around resolved galaxies. With a zero floor, node bounds beyond that horizon are culled before requesting/submitting points. Positive opacity floors bypass that distance cull; normal frustum culling, adaptive budgets and memory limits remain active. The volume has an independent near-plane calculation. Orbit supports a 10-parsec minimum distance and flight speed down to 1 parsec/sec.

## Name search

For full DR1, Visit lazily loads the 1.46 MB `galaxy-search.json` once. Its 17,320 entries combine SGA NGC/IC/UGC names and OpenNGC galaxy aliases; 3,181 have verified visit destinations. The source checksum and catalog ID must match the active full DR1 manifest. The search normalizes case, spacing, padded numbers, and Messier aliases, ranks exact matches before prefixes and substrings, and displays at most eight suggestions. The empty search suggests the Milky Way, six independent nearby destinations and an available DESI example. There is no runtime astronomy-service query or DOM element per catalog galaxy.

`scripts/download_search_sources.py` obtains three filtered SGA FITS downloads (NGC, IC and UGC) and OpenNGC aliases. `scripts/prepare_galaxy_search.py` joins accepted DESI rows through exact `REF_CAT=L3` and `REF_ID=SGA_ID`, requires agreement within 3 arcsec of the SGA center, then prefers the closest central match (redshift-fit significance breaks ties). This avoids linking a nearby knot as the galaxy center. The script verifies leaf point/metadata checksums and exact target IDs, retaining the existing derived distance, leaf node and row. Source hashes are recorded in the name index. OpenNGC-derived names are credited to Mattia Verga, CC BY-SA 4.0; the derived index carries that license.

Entries without such matches remain searchable in a separate, noninteractive explanation panel; no coordinate or distance is invented. Search counts distinguish name matches from available visit locations. Only visitable matches enter the combobox list and its keyboard selection; unavailable-only and empty results clear the active option and collapse the listbox. Browse available galaxies clears the query and restores the verified nearby suggestions. Common matching aliases appear prominently in unavailable-name details. This small named subset is not the percentage of all atlas galaxies that are cataloged. Visiting a result loads its checksum-verified metadata through the existing worker, checks the exact target ID again, and selects/focuses it. Navigation serials prevent a late metadata result overriding a newer camera action. The Milky Way result calls `visitMilkyWay` to focus the sourced Galactic center. The observer marker stays at zero.

## Delivery

Ordinary local builds use `dist`. Cloudflare Pages release builds use isolated `dist-pages`, with an allowlist of full-data assets, complete attribution and a content-fingerprinted `/data/releases/<fingerprint>/` hierarchy. Release packaging verifies every binary SHA-256 and matching catalog/model/search provenance, independently of the active local subset. The catalog pointer is generated in output only; production ignores development dataset-switch queries. Direct Upload serves the complete static package without a backend or separate storage account. Raw downloads, local caches, binary assets and private deployment configuration stay outside Git. `scripts/deploy-pages.mjs` reads ignored `.deploy/cloudflare.json` solely for Wrangler; hosting account values never enter client builds. The application performs no runtime calls to astronomy services and stores no personal data. See [public delivery](public-delivery.md) for caching, old-tab behavior, limits and license boundaries.

## Model visibility and navigation intent

`ResolvedGalaxy.update` combines ordinary point-to-model LOD with a viewport-relative obstruction fade for incidental models. Its single blend drives volume light, arm/clump light, and the complementary catalog point; suppressed bodies do not intercept picking. `Explorer` tracks explicit galaxy focus separately from inspection, protects both identities within the existing 12-model pool, and clears focus intent on observer/overview navigation. Points-only and focused-only display skip automatic candidate scans. Offscreen models reset their blend so they cannot shorten the distance-fading horizon.

A focused galaxy's angular scale also determines its local distance-fading horizon independently of display mode, so points-only does not brighten the distant background. Name search supplies `visitCatalog` a current-intent guard checked before and after asynchronous work; the guard includes dialog visibility and request identity, covering the gap before a native dialog's queued close event. The inspector separates its fixed identity/actions header from its scrolling detail body.

## Milky Way reference integration

`GalaxyVolume` owns the reusable light rendering. `ResolvedGalaxy` supplies a catalog identity and measured sky deprojection; `MilkyWay` supplies independent reference geometry generated by Astropy. The fixed home model uses its own emission/absorption shader with a 512×512 procedural density field, 64 ray cells, a smooth bar/bulge and thin dust/starlight layers (one draw, 2,446,676 tracked texture bytes). It inherits shared bounds, camera-relative coordinates, picking and fades beside the existing maximum of 12 resident catalog models. It never enters point IDs, metadata, sidecar counts, or pair measurements.

The observer origin is the Solar System, not the Galactic center. `homeFocused` controls its close-up exemption separately from catalog focus; `homeSelected` controls the reference inspector while preserving the previous catalog selection. The Milky Way toolbar action and name search use `visitMilkyWay` to focus the Galactic center from 60 kpc with an oblique disk view. Only the explicit Sun / Observer action uses `focusObserver` to target the origin. `homeView` derives the active focus from the real orbit target, clearing the active indicator after a pan. Separate core and Sun annotations retain their physical positions; the core label is suppressed when the two labels would overlap. Ordinary catalog selection restores the normal inspector. Points-only still hides the reference volumes. The camera near plane adapts down at local scales so the Sun marker is not clipped when zooming to the 10 pc orbit minimum.

See [the sourced reference model](milky-way.md) for coordinates, assumptions and reproduction. `?hometest` exercises the real toolbar, search, wheel zoom and separate Sun focus before checking reference-body picking, inside/near-Sun rendering, display choices, marker clipping, data preservation and graphics recovery. Its isolated appearance probe also compares face-on/inclined/edge-on/inside views, dust attenuation, highlight clipping, deterministic redraws, small orbit changes and the single-draw resource budget.

## Local-distance display safeguard

`src/local-distances.ts` defines the current 1 Mpc observer-distance guard for redshift-only catalog records. Prepared binaries, full coverage and float64 metadata remain unchanged. The point vertex shader reconstructs observer-relative position from its chunk-relative attribute and a per-chunk origin uniform; only chunk bounds intersecting the guard activate this calculation. Visual and GPU ID passes share the hidden/raw setting, and the discard is applied after distance opacity so even a 100% floor or disabled fading cannot reveal hidden locals. Revealed points are amber. No extra per-record attributes, draw calls or metadata downloads are introduced by the filter.

Automatic model candidates skip guarded positions, and metadata-based model construction rejects them even for explicit selection. Picking and visits recheck the decoded distance. Changing the policy cancels in-flight selection intent, updates annotations and inspector/measurement notices, and saves `atlas-show-uncertain-local`; the default is false. Original selected records and numerical measurements survive a toggle, while hidden endpoints lose their markers/line. Reference and annotation materials bypass the catalog guard. CPU decisions use float64 distances; shader decisions use existing float32 render positions, so records extremely close to the display threshold can differ at render precision. The threshold is a UI policy, not a claim of scientific certainty above it.

`?hometest` replays all 1,107 actual positions inside the home model's bounding sphere from four orbit angles. A second probe uses a real loaded chunk's nonzero origin, its production render callback and ID material, and the actual settings/visit/model/annotation paths. These full-catalog checks report unavailable for subsets; independent home-reference checks still run there. See [the distance audit](local-distance-audit.md).

## Independently measured nearby galaxies

`nearby-sources.json` pins the six adopted measurements and citations; `prepare_nearby_galaxies.py` generates the small runtime reference, including an excerpt checksum. `nearby-galaxies.ts` adapts it to the shared `ResolvedGalaxy` renderer. `Galaxy.nearby` carries source and uncertainty metadata; redshift fields are null, internal IDs are stable negative integers, and public identities use `nearby:<key>`. The six-entry HUD count is separate from unchanged DESI totals.

The renderer maintains a separate fixed nearby model list and a six-point batch beside the existing 12-slot DESI pool. Shared display/focus policies operate over both lists. Nearby points have their own 12-slot model-blend uniforms and GPU ID namespace (node code 65535, outside the catalog node range). Rendering and picking preserve shared depth across both point scenes. The local scene uses the same camera-relative point shader but bypasses the uncertain-redshift guard; metadata policy checks similarly distinguish independent provenance from redshift-only positions. No per-frame scan of the full catalog is added.

`mergeNearbyNames` deduplicates overlapping name aliases, never survey records. Subsets and failed DESI name-index requests retain the independent nearby entries. Visits use the normal camera/selection path, while the inspector exposes source links and independent-distance errors instead of redshift fields. Measurements distinguish local, mixed-source map, and DESI comoving separations. Six fixed models add 4,032,000 tracked geometry bytes with all spirals, or 2,688,000 with catalog types; a runtime cap rejects more than 12 entries until this layer is redesigned for streaming. [Scientific assumptions and extension contract](nearby-galaxies.md).

## Visual appearance override

`GalaxyAppearance` is independent of model visibility. Explorer defaults to `spiral`; Settings saves `atlas-galaxy-appearance` with either `spiral` or `catalog`. `ResolvedGalaxy` retains its original `data` and chooses rendering parameters separately. Spiral appearance uses the shared illustrative exponential profile, thin oblate deprojection and seeded classic, multi-arm, ringed, tightly wound or feathered disk geometry across source families. Verified road-trip targets use their image-inspired disks, clouds or smooth source profiles in either appearance mode. Radius, projected ellipse, exact center and identity remain unchanged. Milky Way already has spiral structure and retains its reference model.

Changing appearance rebuilds only the bounded resident models, disposing replaced resources and rebinding point/model uniforms. In-flight model requests use the current setting when they finish. The inspector discloses the override and retains the source type and measurement notes. `prepare_spiral_profile.py` reproducibly generates the small common Gaussian approximation; it never edits catalog profiles.

Residency fade is applied to the same blend uniform used by volume light, arms, complementary point visibility and body picking. The existing frame loop advances transitions and remains active until they finish, including when the camera stops. No extra animation timer or catalog-sized update is introduced. `?continuitytest` replays two Andromeda orbits with real streaming and records central-viewport jumps, removal visibility and the resident cap; the appearance probe exercises the real saved setting and source/selection preservation.

## Model color variation

`galaxy-colors.ts` derives a deterministic display palette from the exact string target identity, independent of dense row index, shape seed, camera and model residency. The same palette is used in both appearance modes. Disk and core endpoints are luminance-normalized separately; the core is warmer and brighter, while only a small fraction of illustrative arm/clump samples receive muted pink accents. No age, dust, spectrum or color measurement is inferred from this hash.

The shared smooth volume uses two RGB uniforms for the endpoints. Arm/clump colors are written into the existing color buffer during construction without changing the geometry random sequence, sample positions or sizes. There are no new per-frame calculations, point attributes, textures or draw calls. The Milky Way uses separate illustrative stellar-population colors and dust extinction in its own shader. Distant catalog markers retain their existing navigation colors. `?colortest` compares the same GPU-rendered geometry under two identities, checks reconstruction and color/brightness differences, and repeats after context recovery.

## Related disk recipes

`galaxy-variants.ts` chooses the default appearance's five disk recipes using a hash of the exact target identity, separate from the palette hash. Structure seeds also use that identity, so subset row numbering cannot reshuffle a galaxy's appearance. `spiralLight` is the shared construction boundary: every recipe uses the same Gaussian profile, exposure and sample budget. Catalog-type rendering and the Milky Way reference retain their existing paths.

`spiralSamples` changes angular placement only for the new recipes, preserving each sample's radius, height, size and color under a common seed. Multi-arm disks divide the same samples between four arms. Ringed disks spread half the existing annular samples around a ring, balanced across both arms; the rest retain their spiral paths. All work happens when bounded models are constructed; no additional draw calls, geometry attributes or per-frame calculations are introduced. Development variant diagnostics compare rendered light/highlights and budgets at three inclinations, repeat after context recovery, and can display a side-by-side preview. Color diagnostics now hold the recipe and geometry fixed while changing palettes.

## CMB reference shell

`cosmic-scale.ts` reads a compact reproducible Planck18 reference; `prepare_cosmic_horizon.py` computes the approximate last-scattering radius with Astropy. The comparison uses `manifest.maxDistanceMpc`, including for subsets; it is a linear radius ratio, never a survey completeness estimate.

`cosmic-horizon.ts` traces forward intersections with a fixed sphere at the coordinate origin, normalizing camera coordinates by its 13,884.421 Mpc radius. One full-screen triangle draws a transparent, depth-free background before points and local models. It adds one draw when enabled, zero when disabled, and 36 bytes of geometry with no texture or per-record work. The separate scene cannot enter the GPU ID pass. Derivative filtering softens the silhouette/grid; interior opacity is reduced. The shell is independent of point fading and model residency and disposes its resources with the explorer.

The saved setting changes only visibility. The explicit cosmic-scale view cancels earlier focus/flight using the existing reset lifecycle, clears inspectors, and fits the sphere around the observer for the current aspect ratio. Navigation limits accommodate that view; regular Overview retains the survey framing. `?cosmictest` exercises the actual shader, forward-ray behavior, interior/boundary/exterior views, reconstruction after graphics recovery, settings synchronization, preservation on toggle and origin-centered framing.

## Lookback time rings

`prepare_lookback.py` generates `src/data/lookback.json` with Astropy Planck18: twenty ring definitions (0.01–13.5 Gyr lookback inverted to redshift and present-day comoving distance with `z_at_value`) and a 256-row log-spaced redshift table holding comoving distance and lookback time, plus the measured comoving→lookback interpolation error (1.1 × 10⁻³ Gyr, where the lookback–comoving curve bends most, around z ≈ 1.5 (about 4,500 Mpc); measured at every row midpoint, every ring and random redshifts). `lookback.ts` only interpolates: below the first row (0.44 Mpc) it uses distance ÷ c, exact there to about 10⁻⁴; at and beyond the CMB radius it clamps to the last table value. `formatLookback` follows the three-significant-digit ladder of `formatDistance`. The footer shows the lookback time for the orbit target's distance from the observer. The inspector shows Planck18 lookback for DESI records and distance ÷ c for the independently measured nearby layer, and hides the row for uncertain local positions.

`lookback-rings.ts` shares the CMB shell's overlay body through `screen-overlay.ts`: an isolated scene, one full-screen triangle, a GLSL3 raw shader, transparent and depth-free. It draws the silhouette of each observer-centered sphere in angle form. `chooseRings` runs in float64 on the CPU: rings with r < d, angle asin(r/d) between 1° and the diagonal half field of view, projected radii at least 28 px apart, larger lookbacks preferred, at most eight. The fragment shader compares the angle between each ray and the direction to the origin against those angles with derivative-width anti-aliasing, avoiding the float32 cancellation of a world-space sphere test near the Sun. One draw when enabled and any ring is visible; zero draws when disabled or when the ring set is empty (for example at the 10 pc orbit minimum); 36 bytes of geometry, no texture, no per-record work. The scene never enters the GPU ID pass and is excluded from counts, IDs and measurements.

Labels reuse eight `.ring-label` elements. Each frame the explorer projects the screen-top point of every ring's silhouette circle (center (r²/d)·ĉ, radius r·sqrt(1−r²/d²), offset along the camera's up axis made perpendicular to ĉ) with the observer labels' in-front checks, keeping anchors inside the central 80% of the viewport height (95% of width). The app formats "N ago · D away now" in the active units and drops the distance clause below 600 px width. The saved `atlas-lookback-rings` setting (default off) changes only visibility; `read_atlas_view` reports it. `?lookbacktest` checks exact draw counts, silhouette pixels and checksums before and after context recovery, the empty local ring set, label count/overlap and table monotonicity.

## Survey footprint overlay

`scripts/prepare_survey_footprint.py` streams every checksum-verified leaf metadata chunk of the prepared DR1 catalog, bins RA/Dec into a 720×360 grid of 0.5° cells (rows = Dec south to north, columns = RA 0→360°) and asserts the total equals the manifest count. `public/data/survey-footprint.json` (346 KB) stores the grid as base64 uint8 on a log1p scale (0 = no accepted row, 255 = the densest cell, 2,810 rows in the COSMOS field at RA 149.75° Dec +1.25°) with version, catalog ID, source SHA-256, accepted count, dimensions, occupied-cell and maximum counts, a plain URL source list and a disclosure. 69,895 cells, 33.6% of the sky weighted by cos Dec, are occupied. The release allowlist, hosted verification and `scripts/test_data.py` validate the sidecar against the catalog's source hash and count; the Python check re-bins one leaf independently to pin the row/column convention.

`survey-footprint.ts` fetches the sidecar lazily the first time the toggle is enabled (retrying only after a failure), through the catalog asset path with the explorer's lifecycle signal. `decodeFootprint` requires version 1, the manifest's source SHA-256 and `source.acceptedRows`, so the deterministic development subset keeps the overlay while a sampled bootstrap set fails closed; width, height and decoded length must match. The grid becomes a 720×360 red uint8 `DataTexture` (repeat wrap in RA, clamp in Dec, linear filtering, no mipmaps). The fragment shader ray-traces an observer-centered sphere at `manifest.maxDistanceMpc`, draws both intersections with the CMB shell's near-surface fade, maps each intersection direction to u = RA/360° and v = (Dec + 90°)/180°, and tints by the sampled value in faint cyan, discarding zero, so unsurveyed sky stays dark rather than tinted. Linear texture filtering smooths cell edges by up to half a cell (about 0.25°), so "nothing drawn where the value is 0" holds at cell centres. Because the shell sits at the catalog's farthest distance, the shading is exact only from the origin; elsewhere it is a reference backdrop, not a per-galaxy mask.

The CMB shell, lookback rings and footprint share `screen-overlay.ts`, which owns the triangle geometry, vertex shader, transparent depth-free raw material, camera rotation/lens uniforms and disposal; each overlay adds only its fragment shader and uniforms. The footprint renders after the rings and before the points: one draw when enabled and ready, zero otherwise; 36 bytes of geometry plus 259,200 texture bytes join memory accounting once loaded, and the texture is disposed with the explorer. It never enters the GPU ID pass, counts, IDs or measurements. `state` (idle, loading, ready, failed) and the sidecar's `disclosure` feed the Settings hint from the existing stats tick; the saved `atlas-survey-footprint` setting (default off) changes only visibility, and `read_atlas_view` reports it. `?footprinttest` renders isolated 256² views from the origin toward the densest cell, a surveyed cell beside a real gap and an unsurveyed southern direction, checks frame draw deltas, the missing-sidecar path, saved states and pose/catalog preservation, and repeats after context recovery.

## View links and saved views

`view-link.ts` defines the link grammar `#t=x,y,z&c=dx,dy,dz[&g=identity]`: `t` is the absolute orbit target in Mpc, `c` the camera relative to that target (12 significant digits, so a close orbit around a distant galaxy survives), and `g` one of `sun`, `core`, `nearby:<key>` or `desi:<node>:<row>:<targetId>`. `t` is only a fallback: when `g` resolves, the exact catalog position becomes the target and the decoded offset is applied from it. The decoder is strict and never throws: exactly three finite numbers below 1e6 Mpc in each of `t` and `c`, a node of at most 6 digits, a row of at most 5, a nearby key of at most 16 lowercase alphanumerics and a target ID of at most 20 digits kept as a string (DESI IDs exceed 2⁵³); anything else decodes to null, unknown keys are ignored and the first duplicate wins. The encoder returns null for non-finite or out-of-range values. The dense id is never carried in a link.

`Explorer.viewState()` reports the orbit target, camera and the identity being looked at: core or Sun from the home focus, a nearby key, or the selected DESI record's node/row/target ID, which the explorer tracks as `selectedAddress` (set by GPU picks and by-name visits, defaulting to the streamed model's location); a panned home view has none. `applyView(state, seconds)` is the trust boundary. For a DESI identity the dense id is read from the node's points chunk (resident, or loaded once with priority so frontier retention cannot cancel it), the row's metadata is decoded and its target ID must equal the link's, the model loads when the catalog exists, and the record is selected. An unknown nearby key, an address outside the catalog or a mismatching ID leaves the selection unchanged and focuses the camera alone with the notice "This link points to a galaxy this catalog does not contain."; hidden uncertain-local records keep their existing notice; stale results are dropped by the selection serial.

The app applies `location.hash` once on the first ready frame and then strips it with `history.replaceState`. Production reads the hash, a deliberate departure from ignoring query parameters (see [public delivery](public-delivery.md)). The Share dialog builds links from the live state at click time, copies them (with a visible fallback when the clipboard is unavailable) and stores named views in `localStorage` as `atlas-saved-views` = `{version:1, views:[{name, hash, savedAt}]}`, newest first, at most 50, validated on read with the same decoder; unreadable entries are discarded. Links and saved views carry no personal data. `?sharetest` covers encode/decode on the live camera, links for a named galaxy, a non-resident leaf, Andromeda and the Galactic core, the wrong-ID and out-of-range fallbacks, saved views through the real dialog, a wheel-cancelled travel, an uninterrupted travel matching the instant pose and no visible-model eviction during a hop, repeated after context recovery. ## Tours

`tour.ts` plays one route from `src/data/tours.json` over the explorer's animated visits and never moves the camera itself. `sun`, `localgroup` and `cluster` stops are camera-only `applyView` framings from a stored target along the Milky Way approach direction; `core`, `nearby` and `overview` use `visitMilkyWay`, `visitNearby` and `reset`; the M32 and M110 stop pulls the Andromeda `applyView` back to 0.16 Mpc observer-facing; `cmb` raises an app hook and then `viewCosmicHorizon`. The state machine is travelling → dwelling → next with a single `setTimeout` for the dwell (8 s default, per-stop override) and no second animation loop; every stop uses its own `travelSeconds`, including the first from wherever the camera is. Only an arrival promise resolving `true` dwells: `false` (orbit input, flight or a newer focus took over) or `undefined` (the visit could not start) lands the stop paused, `exit()` and a mid-travel `pause()` invalidate the tour visit token and call `stopTravel()`; pause immediately enters the paused state and clears its arrival pose, so a catalog lookup completing later cannot navigate and Play retries the current destination, and a pose that drifted by more than 1e-6 of the orbit distance during the dwell pauses instead of hopping. `goTo(index, step)` skips an unavailable stop in the direction of travel with a notice; catalog names resolve through `GalaxySearch.find` on the loaded index (null on subsets), and `visitCatalog` re-checks the exact target ID before moving. Hooks: `showCosmicHorizon(true)` applies the shell without persisting and `showCosmicHorizon(false)` restores the saved setting (never force-hides); `onChange` renders the panel; a caption's `{catalogCount}` is replaced with the active manifest's accepted count.

The app pauses the tour on the controls `start` event (immediate; the hop-time pose check is the backstop) and in the capture phase of every navigation control before it moves the camera, exits on Escape when no dialog, flight or auto fly owns the key, hides the galaxy and Milky Way inspectors and the CMB card while `tourActive()`, and reports `tour:{key,index,status}` in `read_atlas_view`. `tourClock.speed` is a development multiplier used only by `?tourtest`, which drives the real Tours button, dialog and panel through both routes at 10×: per-stop framing within 1e-6 relative against `reset`, `viewCosmicHorizon` and the stop data, shell shown at the CMB stop and restored for both saved states, a wheel tick mid-hop pausing with zero target drift, Escape, skip-and-notify on subsets, the 12-model cap and no visible-model eviction during hops, all repeated after context recovery. Stop provenance and the cluster row count are in [tours.md](tours.md).

## Magellanic Cloud volumes

`magellanic-clouds.ts` builds two deterministic 48³ RG density fields (stellar light and dust), assigned only to the existing `nearby:lmc` and `nearby:smc` entries. They replace the generic smooth/spiral light in both appearance modes; the saved `spiral` value is retained and its UI label now reads “Image-inspired targets + spirals”. The exact named disk and smooth portraits described below also apply in either appearance; other identities retain the existing appearance choice. No tour-specific objects, markers, catalogs or camera overrides are created.

`GalaxyVolume` owns one 3D texture and one bounded batch of 4,096 light knots per cloud. CPU fields are cached for only these two identities. Texture sampling integrates 64 cells on the forward ray inside a finite 4.5-radius ellipsoid, using the adopted frame and explicitly assumed thickness; edges taper to empty texture boundaries. Internal dust attenuates the illustrative cloud light. The two draw calls share the existing visibility/residency blend, bounding rectangle, body picking and disposal lifecycle. Each cloud accounts for 671,744 CPU/GPU bytes, slightly less than a 12,000-knot spiral; no catalog-sized field or per-frame procedural noise is added. The existing measured-profile GPU probe explicitly excludes all illustrative cloud and arm light.

The exact nearby identities determine the cloud field and knot seeds; palette inputs retain their existing identity hash, with a fixed cool tint in the cloud volume. These colors and densities are visual choices. `?cloudtest` checks front/reverse/edge/inside/behind views, extinction, stable redraw/reconstruction, highlights, selection and bounded allocations, repeating after graphics recovery. `&cloudpreview` adds a development-only comparison sheet.

## Responsive controls

`mobile-ui.ts` observes viewport width and primary pointer capability through `matchMedia`. It moves the existing controls into a mobile toolbar/menu, retaining IDs, handlers, saved preferences and the single selection/tour state. Comment placeholders restore the original DOM positions when returning to desktop. `mobile-ui.css` scopes all layout overrides to the responsive root attribute. A bounded observer synchronizes the four detail sheets; only the active sheet is displayed, and collapsed content is inert. Canvas pointer input collapses details without intercepting navigation. VisualViewport events keep dialogs above a reduced viewport, and CSS accounts for display safe areas. Disposal restores controls and removes observers/listeners. No rendering, catalog or camera parameters change.
